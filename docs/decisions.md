| D47 | The live prices of D46 are **pushed from the TradeStation quote stream of the client (one stream per 100 symbols)**, and the polling of D46 is the automatic fallback (owner, 2026-10-26, #268). The `ClientCoordinator` holds one `GET /marketdata/stream/quotes/{symbols}` per 100 symbols (SIM host only) carrying the symbols the client's open screens watch (a union of more than 100 symbols is spread over those streams, at most `LIVE_STREAM_MAX_STREAMS` = 5, #275), and pushes each update over a WebSocket (`GET /operar/en-vivo`: browser → web Worker, which checks the session and the `Origin` → the client's own coordinator) to Nueva entrada, the review and the option chain. **The browser keeps one socket for the whole signed-in app** (#278): the `(app)` layout opens it as soon as the page is up, it stays open across client-side navigation, and each screen only changes what it watches (one `watch` with every symbol the screens follow and the entry of the screen that has one; only Nueva entrada and the review send an entry, never on the same page); it is closed when the tab is hidden or the app is left, so no screen pays the connection time again. A stream whose own symbols change is replaced make-before-break (#276): the stream for the new set is opened beside the old one, which keeps delivering until the new one does, so a symbol that stays watched has no gap in ticks (a stream that has not delivered yet is simply restarted); a stream is closed when the sockets watch nothing, and it reconnects with a backoff of `LIVE_STREAM_BACKOFF_BASE_MS` (1 s) doubling to `LIVE_STREAM_BACKOFF_MAX_MS` (30 s). A screen is «on the stream» while its socket is open and something arrived within `LIVE_STREAM_SILENCE_MS` (8 s; the broker's heartbeat counts); otherwise it polls as in D46, and the existing «desactualizado» after 10 s still applies. The price stays display only | lowest latency (a price within a tick instead of within 2 s) and no quotes-budget use per open screen: the snapshot polling costs one request per 2 s per screen, the stream costs one connection per client. A coordinator already stays alive while it holds an outbound stream, so no hibernation is used: sockets die with the object (eviction, deploy), and the page falls back to polling and reconnects. Limits are ours, not TradeStation's: `LIVE_STREAM_MAX_SYMBOLS` (100 per stream, the snapshot's limit) times `LIVE_STREAM_MAX_STREAMS` (5; a screen that would pass 500 symbols keeps polling), `LIVE_STREAM_MAX_SOCKETS` (6 per client), a socket is renewed every `LIVE_STREAM_SOCKET_MAX_MS` (15 min, so the session is checked again) and closed by the page when the tab is hidden. The browser sends only what it watches (account, symbol, asset type or a list of symbols), never a price, SIZE or quantity; the engine sizes the shown quantity from the streamed ask and sizes the order itself from a fresh snapshot ask when it is sent, answering `RECONFIRM` if it moved. Every tick, the entry symbol's too, is pushed to the page at once; the shown quantity follows from a sizing that reads no D1 (#277): the coordinator holds SIZE and the connection row as a read cache (D1 stays their owner), invalidated when the admin saves the client's settings, when the stored connection changes, and after `LIVE_ENTRY_INPUTS_TTL_MS` (60 s); limits are read from the coordinator's storage each tick, so they block entries as soon as they are reached. The 250 ms gap between sizings (`LIVE_ENTRY_MIN_GAP_MS`) is removed: a sizing is memory and local storage only, and ticks that arrive while one runs collapse into the latest, and a failed sizing is not tried again for `LIVE_ENTRY_RETRY_MS` (5 s) so a failing details read is not repeated per tick. The stream was not run against SIM when this was written: its message shape, heartbeat, symbol and concurrent-stream limits are **(verify)** in [tradestation-integration.md](tradestation-integration.md#limits-and-streams) |
| D48 | The daily limit of new entries is **a per-client setting the admin edits** (whole number 1–1000, default 3), stored in `client_settings.max_daily_entries` and read by the engine with SIZE through the cached settings read (owner, 2026-10-27). ### Delegated decisions of 2026-10-21

The owner delegated D19–D22, asking for free, feasible options that keep every confirmed feature. The email question was then settled by the owner: no Cloudflare email option is free for arbitrary recipients (Email Sending needs Workers Paid; Email Routing only reaches verified destination addresses), so **the app sends no email**. The admin hands each client a single-use activation link (72 hours) in person, which replaces the email-OTP step; passkey-only sign-in and recovery codes are unchanged. Resend, Postmark and SES are not needed.

| Decision | Chosen | Why | Rejected |
| --- | --- | --- | --- |
| Trailing % set | {1, 5, 8, 10, 15, 20}, default 10 | the set from the demo the owner proposed; covers tight to wide trails | free-form input (error-prone) |
| Stop bounds | 10–50 %, default 30 | below 10 % a premium stop fires on normal option noise; above 50 % it stops being a protective stop | unbounded |
| Unlock bounds | 30–90 %, default 70 | 30 % is the first scale-out step; 90 % still leaves the last 10 % to trail | values that can never unlock (> 90 %) or unlock before any sale (< 30 %) |
| Adding to a position | not supported in the pilot | simplest rule with no new behavior to get wrong; re-entry after a full close still works | new-position semantics (uses a slot, confusing with the 2-position limit), merging (redefines base, steps, average and protections) |
| Retention | 6 years for orders, fills, events and audit | follows US broker recordkeeping practice (SEC Rule 17a-4); the data is tiny next to the free 5 GB | 1 year (too short for disputes and taxes), indefinite (no bound to plan storage against) |
| Budget | US$0/month on free tiers; Workers Paid (US$5/month) on the triggers in [architecture.md](architecture.md#costs-and-free-tier-limits) | the pilot fits the free limits | paying up front |

## Technical decisions of 2026-10-20

| # | Decision | Why |
| --- | --- | --- |
| T1 | **Two Workers in one repo** (`web` SvelteKit, `engine` with the DO) | adapter-cloudflare can't export DO classes or `scheduled` (kit#13692 open; PRs #13739 and #15627 closed unmerged). Post-build export patching is unsupported |
| T2 | **One DO per client**, mode as a column (refines ONBOARDING's "per client and mode" proposal; confirmed by the owner 2026-10-21) | one TradeStation connection serves both modes; a single owner means a single token refresher and one place for the limits. Every row and key is still mode-scoped |
| T3 | **The DO is the only TradeStation gateway**, including quotes and the chain | no token sharing between Workers; one rate-limit budget per client key |
| T4 | **Polling via DO alarms**, no HTTP streams (the chain is built from the strikes and quotes snapshots: the SIM chain stream never sent `EndSnapshot`, 2026-10-26) | fewer moving parts (no chunk parsing or reconnect logic); polling fits the per-key limits; revisit after the SIM spike |
| T5 | **`OrderConfirmID` = intent id** for idempotency | TradeStation uses it to deduplicate orders; there is no other client tag |
| T6 | **No fills table** | TradeStation reports leg `ExecQuantity` and the average `FilledPrice`; there is no executions endpoint |
| T7 | **`market-calendar`** (port of `pandas_market_calendars`, exact-pinned) for sessions, holidays and early closes; tests check it against NYSE's published dates | TradeStation has no calendar endpoint; a hand-kept date table goes stale. The port is young, so the pinned version and the fixture tests guard upgrades |
| T8 | **App-owned hashed recovery codes** | Better Auth backup codes need TOTP 2FA and are encrypted, not hashed |
| T9 | **Our own UV check** in the passkey `afterVerification` hooks | `@better-auth/passkey` hard-codes `requireUserVerification: false` |
| T10 | **Enrollment session from an activation link** (replaces email OTP, 2026-10-21) | Better Auth needs a session to register a passkey; without email or password, a validated activation link creates a 15-minute session restricted to passkey registration |
| T11 | **Admin overview by fan-out RPC** to client DOs, no read model | a few pilot clients; avoids keeping order state in two places |
| T12 | **One production environment** (SIM) + local | YAGNI; add staging when REAL is prepared |
| T13 | Stop/trailing are **engine-held**: the DO monitors fresh bids and sends a MARKET exit (D36) | decided 2026-10-22; the 2026-10-26 spike confirmed broker `StopMarket` and trailing stops work on options, so a broker-held stop may follow |
| T14 | **Bun** for installs, scripts, unit tests (`bun test`) and ops scripts with Bun-native APIs; Node CLIs (Vite, Wrangler, Vitest, Playwright) launched by Bun but run on Node; no Bun APIs in Worker code | user decision; production runs in workerd, and Wrangler and Playwright require Node |
