# Screens and flows

The overall flow is in [`designs/flow/como-funciona.svg`](../designs/flow/como-funciona.svg): admin invites and configures → 01 Acceso → 02 Compra → 03 TradeStation returns state and fills → 04 Posición (exits, stop, trailing) → 05 Historial.

Designed screens are reproduced from their PNGs. Undesigned screens use the same shell and components ([design-system.md](design-system.md)). On mobile, `Admin` (or `Operar` in the admin panel, which uses the same shell) and `Cerrar sesión` sit in a footer below the content (D38), and the tab bar keeps the three tabs of D29. Every screen has explicit loading, empty, error and confirmation states.

## Client

**Connection alert (every client screen except `/conexion`).** The signed-in layout shows one `role="alert"` block whenever the TradeStation connection cannot be used, read from the connection it already loads (no extra read). It is hidden while `CONNECTED` and healthy (also when `Vence pronto`), and when the engine could not be read (the top bar shows «—»). Never connected: «Conecta tu cuenta de TradeStation para operar», a line saying positions, prices and orders can't be seen or sent, and the link «Conectar con TradeStation». Lost (revoked, expired or refresh failing): «La conexión con TradeStation no está activa», the cause («TradeStation rechazó o cerró la conexión.», «La conexión con TradeStation venció.» or «No pudimos renovar la conexión con TradeStation.»), «Última sincronización correcta: <fecha ET>» when known, «No podemos verificar tus posiciones, precios ni órdenes, ni enviar nuevas, hasta que reconectes.» and the link «Reconectar con TradeStation» to `/conexion`. The token being fine is not enough: while a sync pass has not confirmed the state (a pass failed, or a connect is not reconciled yet) the alert reads «TradeStation aún no confirma tus datos» with the link «Ver la conexión». The last good sync is the engine's last good sync pass (never the token refresh time), the same time `/posiciones` shows. The shell connection is read again on every navigation and every ~30 s while `/posiciones` is open (`app:connection`), so the alert follows a connection that drops or recovers. Admin screens do not show it. While it shows, `/posiciones` (engine `verification: unverified`, which also holds after a failed pass and until a connect is reconciled) and the `/operar` counter «x/2 posiciones · y/N entradas hoy» say «Datos sin verificar desde <fecha ET>» and dim the quantities and counts, because the sync loop is stopped and they are the last values seen. A reconnect restarts the loop; its first pass reconciles against the broker (engine test: a position flat at the broker closes).

### Admin client settings

`?/updateSettings` saves SIZE, stop %, trailing-unlock % and the daily entries limit of one client (`src/lib/server/admin-client-access.ts`). The fields travel together (the daily entries limit may be omitted, which keeps the current one); unknown fields are rejected (400).

- SIZE is whole US dollars (the `size_usd` column), increase only: a lower value is rejected (422 `SIZE_DECREASE`), and so is one whose micro-dollars exceed the safe-integer range (422 `SIZE_INVALID`). The same value is allowed when a percentage changes; a save that changes nothing is rejected (409 `SETTINGS_UNCHANGED`).
- Stop % and unlock % are whole numbers inside the bounds of `src/lib/domain/config.ts`, checked by `validateStopPct` and `validateTrailingUnlockPct` (422 `STOP_PCT_OUT_OF_BOUNDS`, `TRAILING_UNLOCK_PCT_OUT_OF_BOUNDS`) with Spanish messages that quote the bounds.
- The values apply to new entries and new positions only; every open position keeps the stop % and unlock % stored on it. The screen says so next to each field.
- The UPDATE matches the values the check ran against, so a concurrent change fails (409 `SETTINGS_CHANGED`) rather than slipping under the increase-only rule; it commits in one batch with its audit row.
- The daily entries limit (`max_daily_entries`, default 3) is a whole number from 1 to 1000 (`DAILY_ENTRIES_BOUNDS`; 422 `DAILY_ENTRIES_OUT_OF_BOUNDS`, Spanish message quoting the bounds, D48). Unlike SIZE it can go down as well as up, and it blocks new entries only, never exits or cancels. The client's screens show it: `x/2 posiciones · y/N entradas hoy`.
- The 2 open positions are shown read-only from the domain constant; no action changes them.
